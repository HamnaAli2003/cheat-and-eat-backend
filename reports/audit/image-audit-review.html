4.1 Why did these URLs disappear?

No script in backend/scripts/ writes image_source without also setting image_url — every writer sets both columns together in one UPDATE. So the 400 source-without-URL rows were almost certainly produced by an ad-hoc SQL statement / a temporary experiment that was later deleted, not by any surviving Pass script. The Pass-1 records were also lost from the DB at the same time (that's why the receiver of the URL — _tmp_resolve_images.js — found far fewer NULL rows than expected and left 63 rows “needs-review”). This is a data-loss event that predates the current scripts directory.

6. Recommended architecture — ONE clean image-assignment script

Replace the Pass1–4 + buildImagePool + ad-hoc _tmp_* approach with a single, well-structured pipeline built around an explicit, human-reviewable plan. Principles:

  • Never overwrite a GOOD image. “Has URL + title overlap” = locked.
  • No image-pool token matching. Do not copy one food's image onto another unless there is an explicit curated mapping.
  • Per-food candidate search against the Openverse API, then score candidates.
  • Confidence scoring — every candidate is scored, and only HIGH confidence is auto-assigned; everything else goes to a review CSV.

6.2 Candidate scoring (HIGH = auto)

  1. Food/non-food filter — reject titles containing strong non-food words (hotel, restaurant, bottle, poster, …).
  2. Name relevance — token overlap between food name and image title (≥ 2 tokens or 100% for single-token foods).
  3. Category/description relevance — title terms match category descriptors (e.g. “sweet”, “curry”, “rice”, “kebab”).
  4. Single-winner rule — pick the top-scoring candidate; tie → manual.
  5. Reachability gate — optional post-assignment verification; unreachable → revert + queue for review.
  6. Auto-assign only when score ≥ HIGH threshold (e.g. 0.7); everything else → needs-review.csv.

6.3 Execution order (all safe, idempotent)

  1. Run audit → record baseline (this document is that baseline).
  2. Recovery pass for the 201 (restore verified URLs only; keep others in review).
  3. Search + auto-assign HIGH confidence for the ~218 with no candidate.
  4. Manual review list → curated-mappings.json → re-run assign to apply.
  5. Re-run audit → verify no GOOD image was changed and every status moved to GOOD/REVIEW.
